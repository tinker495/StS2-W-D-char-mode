# 카드 미리보기 테스트

사용자 **wjdrb**가 2026-10-25 회고에서 제안한 정식 카드 표시 테스트와 로컬 검증 명령을 “진행”으로 승인해 추가했다. 기대값의 근거는 같은 날 요청한 참조 카드 표시 규칙, 간접 키워드에도 재편 결과 4종과 수호 카드를 표시한다는 “Q1 예” 답변, [카드 표시 합의](../../AGENTS.md#card-reference-previews)다. 임시 관찰의 출력이나 현재 구현을 정답 데이터로 복사하지 않는다.

같은 날 후속 요청에서 사용자는 전사의 타격이 자기 자신인 공격 카드를 재편하므로 시아르쿤 한 장만 표시하도록 확정하고, 기본·강화 두 기대값의 갱신과 실제 원작 카드 초기화 경로의 통합 검사를 승인했다. 이 구체적인 대상 규칙이 이전의 공통 4종 표시 규칙보다 우선한다.

## 실행

[개발 환경](../../README.md#새-pc에서-준비하기)을 준비하고 저장소 루트에서 실행한다. 설치된 게임 DLL과 PCK, .NET 9 SDK, MegaDot 4.5.1, 잠금 파일에 고정된 BaseLib가 필요하다.

```powershell
.\dev.ps1 card-tests
.\dev.ps1 card-tests -Configuration Release
```

명령은 모드와 독립 테스트 호스트를 빌드한 뒤 MegaDot을 창 없이 실행한다. 모델·배치 검사 후 `dev.ps1 publish`로 현재 모드 리소스를 패키징하고 별도 MegaDot 프로세스에서 원작 씬 통합 검사를 실행한다. 이전에 설치한 모드 PCK는 사용하지 않으며 게임에 설치하지 않는다. `-Configuration`은 검사할 모드 DLL의 빌드 구성이며, 호스트 자체는 Godot이 읽는 Debug 폴더에 빌드한다. 기존 `build`, `check`, pre-commit, CI, 애니메이션 검사의 실행 범위는 바꾸지 않는다. 테스트는 [전용 프로젝트](CardPreviewTests.csproj)로 실행하며, 기존 `tests/.gdignore`와 모드의 C# 제외 설정으로 게임 패키지에 들어가지 않는다.

성공하려면 두 검사 프로세스의 종료 코드가 모두 0이어야 하며, 첫 프로세스의 `55 model states, 36 layout cases, 0 failures`와 `CARD_PREVIEW_TESTS_PASSED`, 통합 프로세스의 `18 lifecycle cases, 0 failures`와 `NATIVE_CARD_PREVIEW_TESTS_PASSED`가 모두 있어야 한다. 실패는 종료 코드 1, 초기화·게임 API 호환성 문제는 2로 반환한다. 실행마다 `artifacts/card-tests-<고유 ID>/`에 단계별 UTF-8 로그와 종료 코드 JSON, 엔진 로그, 게임 DLL 버전·SHA256과 통합 검사에 사용한 모드·BaseLib PCK의 SHA256을 남긴다. 엔진의 인증서 저장소 접근 메시지는 기록하고, 다른 엔진 오류·누락된 완료 표시·비정상 종료는 실패로 처리한다.

## 사람이 승인한 기대값

[모델 계약](CardPreviewContracts.cs)은 참조 모델을 명시하고 기본·강화 상태를 각각 실행한다. 구현의 `IsUpgradable` 값으로 검사 수를 줄이지 않는다. 참조 카드 순서는 제한하지 않으며 누락, 중복, 다른 카드, 잘못된 강화 상태, 자기 참조는 실패다.

| 설명의 주체 | 표시할 카드 | 상태 규칙 |
|---|---|---|
| 망혼의 타격, 선조의 한, 불퇴의 저주, 속삭이는 원혼, 모여드는 혼, 망념의 그릇, 영혼 장막 | 망령 | 생성 카드의 강화와 무관하게 기본 망령 |
| 육중한 타격, 광기의 업, 빛바랜 문장 | 각각 의심, 수치, 어리석음 | 기본 원작 카드 |
| 전사의 타격 | 시아르쿤 한 장 | 기본은 시아르쿤, 강화는 시아르쿤+ |
| 찰나의 평정, 위업의 길, 이성의 의지, 해방, 군도의 무예 | 재편 결과 4종 | 대상 선택 전에는 기본 카드 |
| `AltheaPathToGreatnessPower`, `AltheaArchipelagoArtsPower`, `AltheaReformEchoPower` | 재편 결과 4종 | 대상 선택 전에는 기본 카드 |
| `RealtaArcaneShock`, `RealtaSnatch`, `RealtaFathersAdvice`, `RealtaFathersAdvicePower`, `RealtaBronzeWatchdog`, `RealtaKuu` | 강철의 수호자 | 기본 카드 |
| 망령, 재편 결과 4종, 강철의 수호자 | 추가 카드 미리보기 없음 | 자신의 설명에서 다시 자신을 참조하지 않음 |

모델 상태는 총 55개다. 실제 컴파일된 `ExtraHoverTips`와 원작 `HoverTipFactory`를 사용한다. 키워드 텍스트 캐시만 격리된 임시 값으로 채우므로 번역 문구나 글꼴 렌더링은 검증하지 않는다. 기본·강화 원본의 상태도 확인해 강화 실행이 빠져도 통과하지 못하게 한다.

[배치 계약](CardLayoutContracts.cs)은 원작 `NHoverTipCardContainer`와 모드의 Harmony 패치를 실제 Godot `Control` 위에서 실행한다. 설치된 게임 PCK의 `res://scenes/ui/card_hover_tip.tscn` 루트 크기를 입력으로 읽는다. 저장된 스크린샷이나 모드 배치 출력은 기대값으로 쓰지 않는다.

| 입력 | 검사 범위 |
|---|---|
| 화면 크기 | 1280×720, 1920×1080, 2560×1440 |
| 카드 수 | 1장, 2장, 4장 |
| 모델 구성 | 모드 카드 묶음, 원작 카드 묶음 |
| 정렬 | 화면 왼쪽 기준 우측 배치, 오른쪽 기준 좌측 배치 |

총 36개 조합에서 카드 수·크기를 보존하고 겹치지 않아야 한다. 모드 카드 묶음은 컨테이너와 모든 카드가 화면 안에 있어야 한다. 원작 카드만 있는 묶음은 기존 세로 배치와 간격 4를 유지한다. 이 원작 배치의 기준은 게임 DLL 제품 버전 `0.1.0+59260271157f76a2896f0eab5bc6ea1245d8b314`에서 확인했다. 게임 업데이트로 API나 씬 구조가 달라지면 실패 원인을 조사하고, 기대값 변경은 사용자에게 결정받는다.

## 원작 카드 초기화 통합 검사

[통합 검사](NativeCardLayoutTests.cs)는 `NHoverTipSet.CreateAndShow`에 실제 모델의 `HoverTips`를 넘긴다. 설치 게임과 복원한 BaseLib, 이번 소스로 패키징한 모드의 리소스를 읽고, 원작 `card_hover_tip.tscn`과 `card.tscn`을 생성한다. 미리보기 `NCard`의 `_Ready`와 `Reload`를 생략하거나 노드 이름을 강제로 설정하지 않는다. editor 기능을 가진 MegaDot에서 실행하며 실제 카드의 준비 완료와 `Card`에서 바뀐 이름도 확인한다.

| 입력 | 검사 범위 |
|---|---|
| 원본 | 찰나의 평정, 전사의 타격, 전사의 타격+ |
| 화면 크기 | 1280×720, 1920×1080, 2560×1440 |
| 정렬 | 좌·우 |
| 기대 카드 | 찰나의 평정은 기본 재편 4종, 전사의 타격은 시아르쿤, 전사의 타격+는 시아르쿤+ |

18개 조건에서 카드 종류·강화 상태, 원작 초기화, 화면 범위·겹침·크기를 검사한다. 원작 씬을 초기화 전 별도로 생성해 읽은 크기를 기준으로 삼고 스크린샷을 기대값으로 쓰지 않는다. `TestGame`은 전체 게임 시작만 생략하며 카드 자체는 원작 타입을 사용한다. 한국어 지역화·모델·직렬화 ID 캐시를 초기화하고 `MockGodotFileIo`로 저장 I/O를 메모리에 격리한다. BaseLib 3.4.7의 `ModConfig`는 `SaveManager`를 통하지 않고 `OS.GetUserDataDir()` 아래에 직접 설정을 쓰므로, 이 파일시스템 경계만 테스트 프로세스에서 바꾸어 이번 실행의 `artifacts/card-tests-<고유 ID>/user-data/`에 저장한다.

실제 게임 플레이, 카드 그림·지역화된 글자의 시각 품질, 텍스트 설명 상자와 카드 상자의 상호 배치, 임의 위치의 전체 툴팁 보정, 실제 저장 파일, 설치 후 동작은 이 테스트 범위에 포함하지 않는다. 기존 모델·배치 검사의 `TestCard`는 시각 리소스를 생략하는 가벼운 호스트로 유지한다.

전사의 타격의 기본·강화 두 모델 사례는 변경 전 4종을 반환해 실패하고, 시아르쿤만 연결한 뒤 통과하는 것을 확인했다. 원작 노드 이름 조회 결함도 임시로 재주입해 민감도를 확인했다. `%Card`로만 찾는 과거의 배치 조건에서는 기존 모델·배치 91개 조건이 통과한 반면 새 통합 검사의 720·1080 높이, 좌·우 정렬 네 조건에서 화면 넘침을 검출했다. 결함을 제거하면 통합 검사 18개 조건이 통과한다. 결함 주입 스크립트와 실행 로그는 임시 관찰 자료로만 보관한다.
