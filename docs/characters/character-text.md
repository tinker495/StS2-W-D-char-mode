# 캐릭터 소개문·대화 작성 안내

모드의 현재·향후 캐릭터가 같은 형식으로 소개문과 대사를 작성하는 **캐릭터 문장 프리셋**이다. 2026-10-20 설계 대화에서 게임 연결용 뼈대와 한국어 안내를 만들고, 실제 원고는 비워 두기로 합의했다. 원작이 지원하는 문장 자리를 연결하며, 새로운 전투·상점·휴식 대사 연출은 아래 확장 후보로 둔다.

빈 프리셋을 배포하면 지금의 문구와 대화가 유지된다. 한국어를 기준 원고로 사용하고, 영어가 비었으면 완성된 한국어 원고를 표시한다. 문장을 작성한 뒤에는 패키징과 게임 재시작이 필요하다.

## 1. 어디에 작성하나

| 대상 | 실제 작성 파일 | 게임 모델 ID |
|---|---|---|
| 레아르타 | [realta.json](../../Sts2WD/character_text/realta.json) | `STS2WD-REALTA` |
| Althea | [althea.json](../../Sts2WD/character_text/althea.json) | `STS2WD-CHARACTER_TWO` |
| 캐릭터 3 | [character_three.json](../../Sts2WD/character_text/character_three.json) | `STS2WD-CHARACTER_THREE` |
| 캐릭터 4 | [character_four.json](../../Sts2WD/character_text/character_four.json) | `STS2WD-CHARACTER_FOUR` |
| 새 캐릭터용 복사본 | [_template.json](../../Sts2WD/character_text/_template.json) | 복사 후 실제 모델 ID로 변경 |

각 파일에는 캐릭터 문구 15종, 고대 존재 9종 각각의 첫 만남·재방문·반복 대화, 유물 이야기와 `SEA_GLASS`의 이름을 넣을 자리가 있다. 대화 칸은 필요에 따라 늘리거나 줄일 수 있다. 레아르타에는 현재 전용 유물 5종의 빈칸도 준비되어 있다.

말투와 설정을 먼저 정리하려면 [캐릭터 문장 설계 양식](character-voice-template.md)을 복사해 `docs/characters/<char>/<char>-voice.md`에 작성한다. 이 양식은 집필용이며 게임이 읽는 파일은 위 JSON이다. 레아르타의 확정 설정·기획은 [realta.md](realta/realta.md)를 함께 확인한다. 카드 이름이나 그림만 보고 성격·혈연·과거를 확정하지 않는다.

## 2. 빈칸·번역·기존 문구

한 문장의 기본 형식은 다음과 같다. `kor`, `eng` 안에 원고를 적는다.

```json
{ "kor": "", "eng": "" }
```

- 빈 문자열과 공백만 있는 문자열은 미작성이다. 두 언어가 모두 비었으면 기존 문구를 바꾸지 않는다.
- 한국어 환경에서는 한국어, 없으면 영어를 사용한다. 영어 환경에서는 영어, 없으면 한국어를 사용한다. 그 외 언어에는 게임의 영어 fallback을 통해 같은 원고가 전달된다.
- 소개문·호칭·유물 이야기는 항목별로 대체한다. 고대 존재 대화는 **대화 전체가 완성된 언어 하나**를 선택한다. 한국어 한 줄과 영어 한 줄만 채웠다면 완성된 대화로 취급하지 않는다.
- 대사의 화자·순서·반복 여부·방문 조건은 두 언어가 공유한다. 번역에 따라 대화 구조를 바꾸지 않는다.
- 대화의 `next`는 선택 사항이다. 해당 언어에서 비어 있으면 `계속` 또는 `Continue`를 사용한다.
- 원작이나 기존 모드의 임시 문구는 별도의 기초 번역 파일에 남는다. 프리셋 원고를 다시 비우고 패키징하면 그 기초 문구로 돌아간다. 원고 작성은 프리셋에서 진행하고 같은 문구를 두 곳에서 관리하지 않는다.
- JSON 문자열 안의 줄바꿈은 `\n`, 큰따옴표는 `\"`로 적는다. `{Prerequisite}` 같은 게임 변수와 사용 중인 서식 태그를 임의로 번역하지 않는다.

잘못된 모델 ID·필드·화자·조건이나 JSON 문법 오류는 로그에 기록되며 해당 파일을 건너뛴다. `characterId`가 중복되면 파일 이름순으로 먼저 읽은 파일을 사용하고 뒤의 파일은 건너뛴다. 부분 작성된 대화도 로그에 기록하고 건너뛴다.

## 4. 고대의 존재별 대화

| 이름 | `ancients` 안의 키 |
|---|---|
| 니오우 | `NEOW` |
| 다브 | `DARV` |
| 오로바스 | `OROBAS` |
| 파엘 | `PAEL` |
| 테즈카타라 | `TEZCATARA` |
| 노누파이페 | `NONUPEIPE` |
| 탄스 | `TANX` |
| 바쿠 | `VAKUU` |
| 아키텍트 | `THE_ARCHITECT` |

기본 세 칸은 다음 의미다.

| `id` | `visitIndex` | `repeatable` | 용도 |
|---|---|---|---|
| `first_meeting` | `0` | `false` | 그 캐릭터의 첫 방문 |
| `revisit` | `1` | `false` | 그 캐릭터의 두 번째 방문 |
| `repeat` | `null` | `true` | 특정 방문 대사가 선택되지 않을 때 사용할 반복 대화 |

`id`는 작성자가 구분하는 이름이며 같은 고대 존재 안에서 고유해야 한다. 대화를 추가할 때는 복사한 뒤 이 이름도 바꾼다. 대화 번호는 완성된 원고만 모아 자동으로 붙이므로 앞의 빈칸을 억지로 채울 필요가 없다.

`visitIndex`는 **이미 방문한 횟수**다. `4`이면 다섯 번째 방문에 해당한다. 정수 조건과 `repeatable: true`를 함께 쓰면 그 방문에서 사용되고 이후 반복 후보에도 들어간다. `null`은 특정 방문 조건 없이 반복 후보로 쓰는 뜻이며 `repeatable: true`와 함께 사용한다. 같은 횟수에 여러 대화를 지정하면 그중 하나를 게임이 고른다.

대화 한 개의 빈 양식:

```json
{
  "id": "first_meeting",
  "visitIndex": 0,
  "repeatable": false,
  "lines": [
    {
      "speaker": "ancient",
      "text": { "kor": "", "eng": "" },
      "next": { "kor": "", "eng": "" }
    },
    {
      "speaker": "char",
      "text": { "kor": "", "eng": "" }
    }
  ]
}
```

- `ancient`는 상대, `char`는 플레이어 캐릭터다. 순서를 바꾸거나 같은 화자가 연속해서 말하게 할 수 있다.
- 한 줄로 끝내도 되고 여러 줄로 늘려도 된다. 필요 없는 빈 줄은 지운다. 남겨 둔 줄의 `text`는 한 언어에서 전부 채워야 한다.
- `next`는 다음 줄로 넘기는 버튼 문구다. 분기 선택지가 아니며 마지막 줄에서는 사용하지 않는다.
- 필요하면 줄에 `"sfx": ""`를 추가해 이미 존재하는 사운드 경로를 지정할 수 있다. 빈칸은 별도 사운드 지정이 없다는 뜻이며, 일반 고대 존재의 기본 효과음 처리는 원작을 따른다.
- 보상 선택에 따른 새로운 분기·체력 조건·특정 유물 소지 조건은 이 프리셋에 없다. `visitIndex`와 반복 풀은 원작이 제공하는 조건이다.

### 일반 고대 존재의 선택 순서

게임은 전체 캐릭터를 통틀어 처음 만나는 대화, 해당 캐릭터의 방문 횟수에 맞는 대화, 공용 대화의 방문 조건, 반복 대화 풀 순서로 찾는다. 전체 최초 방문 대사가 먼저 나오면 그 방문에는 캐릭터의 `first_meeting`이 나오지 않을 수 있다.

반복 풀에는 캐릭터 전용 대화와 원작의 공용 대화가 함께 들어간다. 프리셋을 채운다고 모든 방문을 전용 대화로 독점하지 않는다. 작성하지 않은 고대 존재는 기존 공용 대화를 계속 사용한다.

### 아키텍트의 차이

아키텍트의 `visitIndex`는 방문 수가 아니라 **해당 캐릭터의 누적 승리 수 `TotalWins`**와 비교한다. 따라서 `first_meeting`은 승리 수 0, `revisit`은 승리 수 1일 때의 자리다.

아키텍트 대화에는 다음 두 필드도 있다.

```json
"startAttackers": "None",
"endAttackers": "Both"
```

각 값은 `None`, `Player`, `Architect`, `Both` 중 하나다. 대화 시작·종료 시 누가 공격 연출을 하는지 정한다. 공격 연출을 바꾸려는 의도가 없다면 준비된 값을 유지한다.

아키텍트는 공용 `ANY` 대화가 없다. 현재 네 캐릭터는 기존 0번 반복 대사를 예비 대사로 갖고 있다. 전용 첫 만남이나 일부 승리 횟수의 원고만 채우면 이 예비 대사를 반복 풀에 보존한다. 처음부터 반복할 수 있는 완성된 대화(`visitIndex: null`, `repeatable: true`)를 채우면 프리셋이 그 역할까지 맡는다.

예비 대사는 특정 승리 횟수와 직접 일치하지 않게 연결하므로 작성한 첫 만남을 대신하지 않는다. 다만 특정 횟수 이후에만 반복할 전용 대화와는 반복 풀에서 함께 선택될 수 있다. 새 캐릭터처럼 기존 예비 대사가 없다면, 항상 사용할 수 있는 반복 대화를 먼저 완성해야 아키텍트 대화를 연결한다.

## 5. 유물 이야기와 그 밖의 문장

`relicFlavor`에는 전용 유물의 **전체 모델 ID**와 문장을 적는다. 게임의 유물 상세 화면에 표시되는 `.flavor`로 연결된다. 레아르타의 청동의 번견·쿠우·마녀 고깔모자·용의 망토·엘디르 그라므르에는 이미 빈칸이 있다.

캐릭터 2·3·4의 목록은 비어 있다. 전용 유물 모델을 만든 뒤 항목을 추가한다. 임시로 공유하는 원작 유물의 플레이버를 바꾸면 다른 캐릭터에도 영향을 주므로 이 프리셋에서는 `STS2WD-` 모델만 받는다.

`seaGlassTitle`은 원작 `SeaGlass` 유물의 캐릭터별 이름(`SEA_GLASS.<캐릭터 ID>.title`)이다. 대사가 아니라 캐릭터를 드러내는 이름 자리다.

카드·포션·파워·인챈트의 이름과 효과 설명은 이미 `Sts2WD/localization/kor/`와 `eng/`의 해당 JSON에 있다. 기능 설명의 정확성을 유지하면서 이름·표현에 캐릭터성을 담을 수 있다. 이 프리셋은 그 효과 설명을 복제하지 않는다. 카드·포션에 임의의 `.flavor` 키를 추가하는 것만으로 새 이야기 칸이 생기지는 않는다.

## 6. 새 캐릭터에 적용하기

1. `_template.json`을 같은 폴더에 새 이름으로 복사한다. `_`로 시작하는 파일은 게임이 읽지 않는다.
2. `characterId`를 등록된 모델 ID로 바꾼다. 표시 이름이나 `CharacterId`라는 C# 상수 대신 실제 모델 ID를 사용한다. 예를 들어 현재 캐릭터 4의 모델 ID는 `STS2WD-CHARACTER_FOUR`다.
3. 새 캐릭터의 기본 현지화·모델 등록은 기존 캐릭터 추가 절차대로 준비한다. 빈 프리셋 자체가 모델·해금 조건·필수 기초 문구를 생성하지는 않는다.
4. 소개문·상황 대사·고대 존재 대화를 채운다. 새 캐릭터의 아키텍트 대화에는 항상 사용할 수 있는 반복 대화도 완성한다.
5. 전용 유물이 있다면 `relicFlavor`에 모델 ID를 추가한다. 별도의 C# 캐릭터 목록에 프리셋을 등록할 필요는 없다.
6. 아래 방법으로 패키징하고 게임에서 확인한다.

## 7. 반영과 확인

리포지토리 루트의 PowerShell에서 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\dev.ps1 publish
```

게임에 설치하려면 게임을 닫고 다음 명령을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\dev.ps1 deploy
```

`build`만으로는 수정한 JSON이 PCK에 들어가지 않는다. `publish`는 `artifacts/mods/Sts2WD/`에 패키지를 만들고, `deploy`는 게임 폴더에도 복사한다. 실행 중 파일을 자동으로 다시 읽지 않으므로 수정·설치 후 게임을 재시작한다.

작성한 원고는 다음 실제 화면에서 확인한다.

- 캐릭터 선택 화면의 소개문과 문법에 맞는 이름·대명사.
- 해당 고대 존재의 방문 조건 또는 아키텍트의 누적 승리 조건. 전체 최초 방문 대화가 우선할 수 있다.
- 두 이벤트의 결과 본문과 멀티플레이 핑·죽는 선택 거부.
- 유물 상세 화면의 이야기와 `SeaGlass`의 캐릭터별 이름.
- 한국어·영어 전환 시 대화 줄 수와 화자가 같고, 영어 미작성 부분에 한국어가 표시되는지.

이는 작성자가 확인할 지점의 안내다. 프리셋 제작 시 게임 플레이를 확인했다는 뜻은 아니다.

## 8. 확장 후보: 아직 게임에 연결되지 않는 자리

다음은 [문장 설계 양식](character-voice-template.md)에 구상만 기록한다. 현재 버전에서 캐릭터별 자동 대사 키가 확인되지 않았으며, 필요하면 발생 조건·빈도·표시 방식과 연결 코드를 따로 설계한다.

| 상황 | 작성해 둘 관점 |
|---|---|
| 전투 시작·엘리트·보스 조우 | 위협을 보는 기준, 상대를 부르는 호칭 |
| 피격·위기·회복 | 약한 모습을 드러내는 방식, 도움을 받는 태도 |
| 승리·패배·죽음·부활 | 자부심, 후회, 집착, 두려움 |
| 상점 입장·구매·거절 | 돈·물건·상인에 대한 태도 |
| 휴식·강화·야영 | 긴장이 풀렸을 때의 습관, 장비와의 관계 |
| 동료별 대화·구조·협력 | 친밀도, 갈등, 서로만 아는 일 |
| 일반 이벤트 선택·결과 | 가치관이 실제 선택으로 드러나는 지점 |
| 특정 카드·유물·지역 반응 | 반복 소재와 기억의 연결 |
| 엔딩·기록·도감 | 여정 전후의 변화와 남기는 문장 |

원작 상인 대화는 상인의 공통 대사 풀이고 휴식 설명에는 캐릭터 변수가 쓰인다. 두 곳 모두 이 프리셋의 키를 추가하는 것만으로 캐릭터의 응답 말풍선이 생기지는 않는다.

## 9. 연결 근거와 유지보수

확인 기준은 설치 게임 **v0.107.1, commit `59260271`**, BaseLib **3.4.7**이다. 설치 PCK의 한국어 `characters.json`·`ancients.json` 및 아래 타입·멤버를 대조했다. 로컬 조사용 사본 없이도 같은 버전의 설치 자료와 다음 식별자로 다시 확인할 수 있다.

| 근거 | 확인한 동작 |
|---|---|
| `CharacterModel`, `NCharacterSelectScreen.SelectCharacter` | 이름·소개문·문법·해금·모디파이어 문구 |
| `SunkenTreasury.SecondChest`, `AromaOfChaos.MaintainControl` | 두 이벤트 전용 문구 |
| `NEventOptionButton.OnRelease`, `FlavorSynchronizer`의 턴 종료 핑 처리 | 죽는 선택 거부·멀티플레이 말풍선 |
| `RelicModel.Flavor`, `NInspectRelicScreen`, `SeaGlass.Title` | 유물 이야기·캐릭터별 유물 이름 |
| `AncientDialogueSet.GetValidDialogues`, `PopulateLocKeys`, `AncientDialogue.PopulateLines` | 방문 우선순위·반복 풀·화자·버튼 |
| `AncientEventModel.DialogueSet`, `TheArchitect.DialogueSet` 및 승리 수 조회 | 대화 구조 캐시·아키텍트의 차이 |
| BaseLib `AddAncientDialogues`, `AncientDialogueUtil.GetDialoguesForKey` | 모드 캐릭터 대화 등록·연속 번호 규칙 |
| `LocManager.LoadTable`, `LocTable` | 번역 병합과 영어 fallback |

[연결 코드](../../Sts2WDCode/Localization/CharacterTextLocalization.cs)는 이 모드의 `characters.json`, `ancients.json`, `relics.json`을 읽는 지점에서만 원고를 병합한다. [프리셋 처리](../../Sts2WDCode/Localization/CharacterTextPreset.cs)가 빈칸 제외·언어 선택·연속 번호·화자·버튼·반복 접미사·방문 조건을 담당하고, 대화 등록과 선택은 기존 BaseLib·게임 코드를 사용한다.

완성된 대화의 키 형식은 `<ANCIENT>.talk.<CHAR>.<대화번호>-<줄번호>[r].ancient` 또는 `.char`다. 반복의 `r`은 모든 줄에 일관되게 붙고, 마지막 줄을 제외하면 `.next`가 생성된다. `visitIndex: null`은 BaseLib의 정수 메타데이터 `-visit: "-1"`로 전달한다. 방문·승리 수는 음수가 아니므로 정확한 횟수에는 일치하지 않으면서 반복 후보로는 사용되는 원작 선택 규칙을 이용한다.

게임이나 BaseLib 버전이 바뀌면 위 멤버와 프리셋 연결을 다시 확인한다. 새 원작 문장 지점은 소비 코드가 확인된 경우에 추가하고, 원고만 넣으면 표시된다고 추정하지 않는다.
