# Realta 파츠 리깅 시도

이 문서는 첫 번째 시도의 기록이다. 이후 공식 비교와 v2 이후의 변경·남은 결함은 [애니메이션 개선 기록](realta-animation-iteration-log.md)에 있다. 아래 v1의 재생성과 배치 제안은 후속 반복에서 원본 mask 보존·국소 재생성 방식으로 수정됐다.

2026-10-19, Codex 내장 이미지 생성 툴로 `base.png`와 현재 `combat.png`를 입력해 12개 파츠 시트를 생성하고 독립 Godot 프로젝트로 조립했다. Gemini API나 별도의 API 키는 사용하지 않았다. 현재 결과는 검토용 초안이며 게임에는 적용하지 않았다.

재사용할 영문 에이전트 지침은 [codex-cutout-rig.md](../../agents/codex-cutout-rig.md)에 있다. 입력 역할, 생성 프롬프트 틀, 파츠 소유, 좌표·Z 규칙과 검증 절차를 포함한다.

## 입력과 분해

- `base.png`: 1152×1728 RGBA. 얼굴·의상·장비·화풍 기준.
- `Sts2WD/images/charui/realta/combat.png`: 384×576 RGBA. 분해할 자세와 실루엣 기준.
- 생성 시트: 1448×1086 RGBA, 네 모서리 알파 0. 머리와 모자는 하나, 각 손과 전완은 하나, 무기는 전체가 하나의 강체다.

생성기는 요청한 4×3 균등 셀 배치를 정확히 지키지 않았다. 실제 위치를 관찰해 추출 사각형을 지정하고 각 영역의 가장 큰 연결 성분에 속하는 원래 RGBA 픽셀을 보존했다. 다른 파츠에서 들어온 분리된 조각은 제외했다. 추출은 요청한 파츠 분해 작업에 해당하며, 그림 일부를 확대해 새 구도를 만드는 작업은 수행하지 않았다.

생성형 분해는 원본 픽셀을 보존하는 세그멘테이션이 아니다. 이 결과에서는 얼굴·무기 비율·의상 세부가 다시 그려졌고, 어깨 갑옷과 커프스가 이웃 파츠에 중복됐다. SIFT 정합으로 정확한 원위치를 보장하지 않고 관절·배율·Z를 명시했다.

## 관절과 파츠

독립 씬은 `Node2D` 루트와 텍스처 없는 `Sprite2D`인 `Visuals`, 그 아래의 `Node2D` 관절과 파츠별 `Sprite2D`로 구성한다. 좌표는 384×576 캔버스의 Godot 픽셀, 회전은 라디안이다. Spine 중간 파일과 좌표 변환은 사용하지 않았다.

```text
Visuals
└─ hip
   ├─ coat
   ├─ thigh_l → shin_l
   ├─ thigh_r → shin_r
   └─ torso
      ├─ head
      ├─ upper_arm_l → forearm_l → grip → weapon
      └─ upper_arm_r → forearm_r
```

`l/r`은 화면에서 보는 좌우다. 관절 Z는 0, 파츠는 `z_as_relative = false`다. 무기는 쥔 손 아래 손잡이 관절을 따라간다.

| 파츠 | ZIndex |
|---|---:|
| coat: 외투 뒷자락 | 0 |
| thigh_r: 화면 오른쪽 허벅지 | 1 |
| shin_r: 화면 오른쪽 무릎·정강이·부츠 | 2 |
| thigh_l: 화면 왼쪽 허벅지 | 3 |
| shin_l: 화면 왼쪽 무릎·정강이·부츠 | 4 |
| upper_arm_r: 화면 오른쪽 상완 | 5 |
| forearm_r: 화면 오른쪽 전완·손 | 6 |
| torso: 몸통·목깃·허리띠·주머니 | 7 |
| upper_arm_l: 화면 왼쪽 상완 | 8 |
| weapon: 빗자루 창 전체 | 9 |
| forearm_l: 화면 왼쪽 전완·쥔 손 | 10 |
| head: 머리·머리카락·모자 | 11 |

| 클립 | 길이 | 동작 |
|---|---:|---|
| idle | 2.4초, 반복 | 작은 몸통·머리·팔·외투 회전, 발 고정 |
| attack | 0.9초 | 몸통과 팔의 준비·스윙·복귀 |
| hit | 0.55초 | 반동 후 복귀 |
| die | 1.2초 | 상체를 숙여 마지막 자세 유지. 완성된 쓰러짐 동작은 아님 |

선형 보간을 사용한다. 각 클립은 애니메이션 대상 여섯 관절의 회전을 모두 기록해 이전 클립의 값이 남지 않게 했다. 전신 이미지를 찌그러뜨리는 스케일 애니메이션은 없다.

## 검증과 남은 문제

MegaDot `4.5.1.m.14.mono.custom_build`에서 PNG import와 씬 인스턴스화를 수행했다. 파츠 12개와 네 클립을 읽었으며, 각 클립 중간 시점의 실제 몸통 회전은 idle 약 −0.012, attack 약 0.010, hit 약 −0.160, die 약 0.160 라디안으로 관찰됐다. 처음에 정수 `0`으로 시작하는 키는 작은 회전이 0으로 처리돼, 키 전체를 `0.0` 같은 실수 리터럴로 바꿨다.

초기 SDK 탐색 문제는 저장소의 `.tools/dotnet`을 `DOTNET_ROOT`와 PATH에 지정해 해결했다. 기본 `user://logs` 생성 실패로 엔진이 한 번 충돌해 작업 폴더의 명시적 `--log-file`로 재실행했다. 재실행은 종료 코드 0이었고 OS 인증서 저장소 읽기 오류 메시지는 남았다.

원본과 조립 결과를 384×576에서 비교하고 240×360 미리보기를 확인했다. 같은 관절·키 데이터로 네 클립을 보여 주는 105프레임 GIF도 만들었다. GIF는 별도 렌더러의 파츠 변환 미리보기이며 게임 화면 녹화가 아니다. 이 관찰들은 정식 테스트나 사용자 승인에 해당하지 않는다.

중복 어깨·커프스, 허벅지와 무릎 연결, 원본과 다른 머리·무기 비율 및 기울기가 남았다. 다음 생성에서는 어깨·커프스의 단일 소유와 파츠 사이 여백을 명시하고, 무기를 원본 비율로 별도 생성할 필요가 있다. 현재 결과는 완성된 자연스러운 전투 애니메이션으로 간주하지 않는다.

기존 C#와 런타임 에셋을 변경하지 않아 모드 빌드·PCK 발행·설치는 수행하지 않았다. 실제 공격·피격·사망 이벤트 연결과 인게임 재생도 미검증이다. 기존 테스트·검증 자산을 추가하거나 수정하지 않았다.

## 로컬 결과물

Git에서 제외되는 `drafts/cutout-v1/`에 `parts-atlas.png`, `parts/*.png`, `rig.json`, `cutout.tscn`, `project.godot`, `assembled.png`, `comparison.png`, `animation-preview.gif`, `generation-prompt.txt`를 저장했다. `build_trial.py`는 이번 시트 전용 추출·조립 변환이며 범용 자동 분해기가 아니다. `check_scene.gd`는 임시 관찰 스크립트다.

이 초안 폴더 없이도 입력과 절차를 이해할 수 있도록 필요한 규칙은 위 에이전트 지침과 이 문서에 기록했다. 확률적 이미지 생성이므로 같은 프롬프트로 동일 픽셀이나 배치를 재현할 수는 없다.
