# Reuse Native StS2 Features

Prefer StS2's existing features and extension points for gameplay, commands, models, UI, tooltips, localization, and resource handling. Before adding a mod-owned equivalent or a Harmony patch, inspect the relevant native type, member, and vanilla call site in the installed game. Use the native API directly or through established BaseLib integration points; keep content and presentation changes within that native flow.

Add custom behavior only for a required capability the native implementation lacks or a confirmed defect. Record the game version, relevant type/member, observed limitation, and why existing APIs or extension points are insufficient in the implementation documentation. Keep the extension limited to that gap and preserve native behavior outside it. For named base-game effects and their mappings, follow [ADR-0001](/docs/adr/0001-reuse-base-game-effects.md).

## Runtime Presentation and Lifecycle Guardrails

- **Pooled UI node hygiene (`NCard`, `NEndTurnButton`):** `NCard.InitPool` recycles `card.tscn` instances across the hand, discard pile, card rewards, merchant, and deck screens, and `OnReturnedFromPool` resets only vanilla fields. Likewise, `NEndTurnButton.OnEnable` reapplies vanilla button textures each turn. Reset custom label, border, and plaque overrides inside `NCard.Reload` ([CardAppearance.cs](/Sts2WDCode/Cards/CardAppearance.cs)), and ensure any dynamic child overlay attached to a card self-hides or detaches as soon as the node leaves its owning container (such as `NHandCardHolder`).
- **Session resource caching and dirty-flagged geometry:** Keep shaders, materials, and shared overlay scenes in static `.tres`/`.tscn` resources or process-lifetime caches rather than calling `Shader.new()` or `ResourceLoader.Load` on each combat entry or card play. Gate procedural `Line2D` or `Polygon2D` vertex updates behind state-change dirty flags instead of rebuilding geometry every frame.
- **Fault isolation and combat-end timing:** Purely visual hooks must never delay combat-end state transitions or swallow end-of-combat relic triggers (such as `Meat on the Bone` / `AfterCombatEnd`). Wrap periodic or per-frame non-gameplay visual hooks in a bounded failure counter (circuit breaker) that logs once and disables only the failing visual effect for the session if an upstream game update renames an internal node.
- **Multi-side combat facing (`FlipX`):** In surrounded or two-sided encounters, `NCreature` flips character visuals horizontally. Never hardcode screen-right (`+X`) rotations, offsets, or projectile origins that override or conflict with the parent creature's facing state.
- **Native `SpineSprite` rigs and `guard` trigger routing:** Per [ADR-0008](/docs/adr/0008-native-spine-rigs-and-artifact-refresh.md), target native `SpineSprite` (`libspine_godot` `.spjson` + `.spatlas` + `SpineSkeletonDataResource`) for `combat`, `merchant`, and `char_select_bg` (`NSpineAutoPlayer`) while keeping `rest_site` on Stage-Inpaint seated illustrations ([seated_illustration.gd](/Sts2WD/scenes/rest_site/seated_illustration.gd)). Standard combat rigs expose `idle_loop`, `attack`, `guard`, `hurt`, `cast`, and `die` (plus `relaxed_loop` for merchant and Track 1 independent blink/expression overlays): Block-granting `CardType.Skill` cards route to `guard` by default, `CardType.Attack` cards retain `attack` priority even when granting Block, and `Sts2WDCard` may override the trigger per card.
- **Developer console extensions:** Implement QA and inspection shortcuts by subclassing `MegaCrit.Sts2.Core.DevConsole.ConsoleCommands.AbstractConsoleCmd` ([WdConsoleCmd.cs](/Sts2WDCode/DevConsole/WdConsoleCmd.cs)), which `DevConsole` auto-discovers across mod assemblies without Harmony patches.
