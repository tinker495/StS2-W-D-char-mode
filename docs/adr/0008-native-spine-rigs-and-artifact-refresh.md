# Native Spine Rigs, Character Kits, and Mandatory Artifact Refresh

Standardize playable-character combat, merchant, and character-select animations on Slay the Spire 2's native `SpineSprite` runtime (`libspine_godot` `4.2` `.spjson` + `.spatlas` + `SpineSkeletonDataResource`) compiled from verified `rig-c` (`4.3`) sources, and require every toolchain or standard-pipeline update in this repository to refresh or migrate existing tracked outputs rather than leaving legacy characters on superseded pipelines.

## Context and Decisions

1. **Mandatory artifact refresh on toolchain or pipeline updates:** Updating an authoring, compilation, or packaging tool (such as the local `rig-c` toolchain) or adopting a new repository-wide asset/runtime standard requires rebuilding and refreshing existing tracked outputs—either within the same change for same-format upgrades or through an ordered, dependency-linked migration chain for structural transitions. Leaving earlier characters permanently on legacy formats fragments validation gates (`tests/check_rig.gd`, PCK allowlists) and multiplies runtime maintenance paths.
2. **`rig-c` (`4.3` verification) → native `SpineSprite` (`4.2` runtime) across `combat`, `merchant`, and `char_select_bg`:** Baking `rig-c` outputs into Godot `Skeleton2D` + `Polygon2D` + `AnimationPlayer` ([sts2-cutout-runtime-contract.md](/docs/research/sts2-cutout-runtime-contract.md)) forces non-Spine BaseLib dispatch aliases, custom game-over bridges, single-track mixing, and no runtime Spine `physics` constraints. Installed `libspine_godot` loads text `.spjson` (Spine `4.2` JSON) and JSON-wrapped `.spatlas` directly through `SpineSkeletonDataResource` without Spine Editor binary exports. Retaining `@rig-c/parts` (pixel-preserving layer decomposition plus hidden-joint-end inpainting) and `rig-c` (`A00`–`A53` assertions and 24 fps `--folds` checks) as the authoring gate while emitting `.spjson`/`.spatlas` unlocks C++ `SpineSprite` playback, runtime `physics`, `SpineSlotNode` attachments, `NSpineAutoPlayer` selection scenes, Track 1 independent blink/expression overlays, and a standard `6 + 1` clip contract (`idle_loop`, `attack`, `guard`, `hurt`, `cast`, `die` + `relaxed_loop`). Because vanilla StS2 plays no character animation on Block cards, `CardType.Skill` cards that grant Block trigger `guard` by default (`CardType.Attack` retains `attack` priority, with per-card override support on `Sts2WDCard`). Rest-site scenes (`rest_site.tscn`) intentionally stay on the four-layer Stage-Inpaint seated illustration pipeline ([ARTS.md](/ARTS.md#511-rest-site-seated-illustrations)) augmented with live campfire flicker.
3. **Character kits, lightweight grounded presentation, and deferred SFX:** Before bulk card or rig authoring, characters may establish tracked turnaround/prop and expression masters (`docs/characters/<char>/kit-*.png`) while keeping disposable candidate boards and generation provenance (`<topic>-lineage.json`) inside ignored `drafts/`. Combat/merchant grounding uses a shared shader-driven soft contact shadow ([ground_shadow.tscn](/Sts2WD/scenes/shared/ground_shadow.tscn)) and rest sites share synchronized campfire flicker ([seated_illustration.gd](/Sts2WD/scenes/rest_site/seated_illustration.gd)); heavy cut-in or finisher overlays remain out of scope unless separately approved. Custom audio remains deferred until character SFX assets are introduced, at which point pooled Godot `AudioStreamPlayer` playback on the native `"SFX"` bus (with per-clip debounce and pitch jitter) is preferred over FMOD `.bank` rebuilds.
